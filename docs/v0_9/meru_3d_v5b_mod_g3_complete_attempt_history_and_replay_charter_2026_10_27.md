## 0. Precise G3 qualification question and immutable boundaries

Can an independently implemented, **non-importing** reviewer reconstruct the complete registered **generic** attempt, execution, event and decision history—including success, uncertainty, ordinary failure, contradiction, pre-emption, timeout and interruption—from externally preserved original bytes alone, and refuse any certificate or complete-history claim when a necessary attempted prefix, source binding, worker lifecycle, interval decision or evidence member is missing, contradictory, untrusted or tampered with?

G3 qualifies **recording, chronological/cross-source binding, loss-detection and bounded replay of declared finite work**. It does **not** qualify general mathematical proof soundness (G4), live kernel accounting and process containment (G5), an integrated deployed producer (G6), correctness of the Meru hypothesis, or scientific `RUN_01`. A mathematically plausible recomputation is not proof that the original algorithm executed that sequence. A well-resealed chain is not proof of completeness without an independently trusted inventory/anchor. Old original data that never existed or has been lost is never regenerated and represented as the original.

**Target reviewer disposition:** `MOD_G3_PASS_SCOPE_LIMITED` *only* for complete satisfaction of the G3 charter's own expressly bounded history/replay scope; otherwise `MOD_G3_FAIL`, `MOD_G3_INCOMPLETE`, `MOD_G3_BLOCKED`, or `MOD_G3_EVIDENCE_LOSS_STOP` as evidence warrants. The developer cannot issue a technical PASS; the owner alone may later decide on a separate exact-scope human gate seal.

The unchanged original V5B constraints remain: **30 CPU seconds/view across 128/256 precision**, **45 CPU seconds/unordered pair shared across the four logical branches and permitted precisions**, **6,000 CPU seconds total including orchestration/assembly**, **4 GiB RSS**, **two-hour scientific watchdog**, at most the registered precision attempts, 4,096 directed interval subdivisions and 128 arclength-inversion bisections. ## 2. Required G3 finite-history contract, provenance and trust boundary

Before any code change, Astra must propose an explicit, independently inspectable **versioned finite-history format**, including its canonical bytes, JSON grammar and all permitted status names. The independent reviewer must freeze its *own* class oracles before viewing the completed candidate. The signed requirements constrain the format, not an invented implementation language:

1. **Complete execution inventory:** independently anchored run/object/camera/view/unordered-pair identities, precise 128/256 attempts and four logical pair branches, proposed tasks vs actually launched workers, unattempted/skipped work with explicit reason, partial and terminal states. Distinguish **planned**, **attempted**, **not attempted**, **started**, **partial**, **completed**, **pre-empted**, **failed**, **interrupted**, **crash-unconfirmed**, and **unresolved** without conflating them. No implicit default-zero history or fabricated terminal event.
2. **Stable event and source identities:** unique event/attempt/task/worker IDs and monotonically ordered sequence; parent/child/termination and lifecycle links; exact code/source/diff/schema identity; valid prior-event/hash references and separate externally trusted intake/inventory anchors. Reused IDs, missing events, forged branch/source binding, contradictory worker state and post-hoc resealed chains must fail positive complete-history qualification.
3. **Every genuine intermediate decision:** bound input/preimage hashes, deterministic registered operation or method, precision, applicable arithmetic interval endpoints, directed integration/Darboux partition and cell enclosures, chosen split priorities and tie-breaking decisions, inversion comparison and bisection bracket updates, uncertainty/witness/refusal reason, and registered resource charges wherever actually observed. Store original bounded prefixes even when a computation yields no certificate. A hash of a final result or a discarded-prefix **count** is insufficient.
4. **Worker and interrupted histories:** actual partial payloads must be preserved as they were emitted, with termination/cancellation/pre-emption status and cause, original event-order evidence and status-specific trusted anchors. Where a crash prevents a terminal record, represent an **unconfirmed terminal** and fail closed for any complete-history/successful-certificate assertion; never synthesize a worker event. If a host lacks durable append or kill observability, mark what cannot be observed as `NOT_OBSERVED`.
5. **Exact compatibility:** G1 strict schema, restricted symbolic AST, canonical source hashes, and G2 exact reported CPU charges are mapped by explicit adapters/contracts. No unapproved new parser grammar, fallback to permissive parsing, float/rounding epsilon, CPU threshold tolerance, or allowing a failed attempt to certify a result. G2's trusted inventory is *not* magically authenticated by a self-declared root hash in G3.
6. **Bounded replay:** a reviewer using fresh non-importing code can parse the preserved bytes, check original file and event links and full finite arithmetic/decision chronology, rederive registered deterministic split/merge/bracket-update relations within the G3-admitted representation, verify complete task/branch/precision inventory and status consistency, and refuse invalid or incomplete paths. Replay of a mathematical proof rule beyond its previously independently established scope belongs to G4; G3 cannot silently assume unknown library or FLINT soundness.
7. **Atomicity and interruption resilience:** define the persisted event boundary, checkpoint transition, monotone append semantics and precise crash/recovery rules. A torn ZIP, truncated JSON, missing worker record or deliberately interrupted output produces recoverable **honest partial history**, not a falsely closed complete history. No retroactive insertion into a frozen original or overwrite of an earlier attempt.
8. **Canonical format security:** reject duplicate JSON members where significant, ambiguous numeric types, unsafe ZIP names, directory traversal, member collisions, reference cycles, excessive nesting/size beyond declared bounds and executable deserialization. Verify hashes and CRC; neither a ZIP CRC nor an internally self-consistent signature proves completeness without an external inventory anchor.

**Minimal acceptance evidence model:** every reported *complete* history must be accompanied by original record bytes, an independently anchored expected task/attempt list, full per-event content or verifiable references to retained original contents, a versioned precise grammar, a checked source/dependency tree, a non-importing replay trace, and exact event/record hashes. If a required item is not available, return `INCOMPLETE` / `UNTRUSTED_HISTORY` / `NONCERTIFYING` with accurate rationale rather than assert a complete successful replay. The actual error labels may be versioned but cannot mask outcomes.
